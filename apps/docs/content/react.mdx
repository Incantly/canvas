# React

```sh
npm install @incantly/canvas-react
```

The package re-exports everything from `@incantly/canvas`, so one import
gives you the component *and* the engine (`Store`, `Editor`, diff helpers).

## Basic usage

```jsx
import { Canvas } from '@incantly/canvas-react'
import '@incantly/canvas/canvas.css'

export default function Board() {
  return (
    <div style={{ position: 'fixed', inset: 0 }}>
      <Canvas theme="light" grid="lines" />
    </div>
  )
}
```

The component renders a `div` that fills its container. Give the container
real dimensions.

## Props

| Prop | Type | Default | |
| --- | --- | --- | --- |
| `theme` | `'light' \| 'dark'` | `'light'` | Live-switchable |
| `grid` | `'none' \| 'lines' \| 'ruled' \| 'dots' \| 'crosses' \| 'iso'` | `'lines'` | The backdrop; live-switchable |
| `readonly` | `boolean` | `false` | Lock input (also hides the toolbar) |
| `hideUi` | `boolean` | `false` | Hide the stock toolbar — [bring your own](/docs/headless/) |
| `themeToggle` | `boolean` | `true` | Show the theme switch in the board menu |
| `gridControl` | `boolean` | `true` | Show the grid switch in the board menu |
| `watermark` | `boolean` | `true` | The [corner mark](/docs/watermark/); live-switchable |
| `store` | `Store` | — | External store for [controlled usage](#controlled-usage) |
| `initialSnapshot` | JSON | — | Uncontrolled document loaded once (ignored when `store` is given) |
| `initialCamera` | `{ x, y, z }` | — | Initial camera |
| `initialStyles` | `{ color, size, dash, fill, font }` | — | Initial pen styles |
| `fitOnMount` | `boolean` | `false` | Fit content once after mount |
| `fitOnResize` | `boolean` | `false` | Fit again when the host resizes |
| `uiTools`, `uiIcons`, `hidePagesBar` | — | — | Live toolbar configuration |
| `className`, `style` | — | — | Applied to the host div |

`snapshot`, `camera`, `styles`, and `autoFit` remain as deprecated aliases.
`documentMode`, `touchUi`, and `documentUi` are initialization-only; remount the
component (usually by changing its React `key`) to change them.

## Callbacks

| Prop | Fires |
| --- | --- |
| `onMount(editor, ui)` | Once, after the board is ready |
| `onChange(diff, source, editor)` | Every document change — see [the data model](/docs/data-model/) |
| `onSelectionChange(ids, editor)` | Selection changed |
| `onThemeChange(themeId, editor)` | The in-board switch moved the theme |
| `onGridChange(gridId, editor)` | The in-board switch moved the grid |
| `onSave(blob, background)` | Toolbar PNG export — [intercept it](/docs/export-images/) |

`onThemeChange` / `onGridChange` exist so the board menu's switches can flow
back into your app state:

```jsx
const [theme, setTheme] = useState('light')

<Canvas theme={theme} onThemeChange={setTheme} />
```

## The ref

The ref exposes the whole engine — every imperative API in these docs is
reachable from it:

```jsx
const ref = useRef(null)

<Canvas ref={ref} />

ref.current.editor.setTool('draw')
ref.current.editor.fitContent({ animate: 220 })
ref.current.editor.store.undo()
ref.current.ui.setHidden(true)

// Safe persistence boundaries: pending rich-text input is flushed first.
const snapshot = ref.current.getSnapshot()
ref.current.loadSnapshot(nextSnapshot, true)
```

## Controlled usage

Pass your own `Store` when the document outlives the component — shared
between views, preloaded before render, or synced with peers:

```jsx
import { Canvas, useCanvasStore } from '@incantly/canvas-react'

function App({ savedSnapshot }) {
  const store = useCanvasStore(savedSnapshot) // stable across renders
  return <Canvas store={store} />
}
```

Two components rendering the same `store` show the same live document —
that's the quickest way to see the [sync model](/docs/sync/) working.

If a remote store update arrives while the rich-text document has a focused
local draft, the editor preserves both versions and emits `documentconflict`.
Resolve it explicitly with `editor.resolveDocumentConflict('local')` or
`editor.resolveDocumentConflict('remote')`.

## Rendering and fonts

`Canvas` requires the browser DOM, so render it from a client component in SSR
frameworks. The package CSS uses system fallbacks and makes no runtime font
request. Load any preferred web fonts in your application shell.

React Strict Mode's development mount-cleanup-mount cycle is supported. Keep an
external `Store` when document state must survive a remount; the component
flushes pending rich-text input during cleanup.
