# Performance

Incantly coalesces rendering through `requestAnimationFrame`, culls offscreen pages and shapes, caches geometry and text layout, batches store transactions, and caps canvas DPR to control fill cost and memory.

The detailed [project performance plan](https://github.com/incantly/canvas/blob/main/PERFORMANCE_PLAN.md) adapts the proven principles in [tldraw's performance guide](https://tldraw.dev/sdk-features/performance) to Incantly's Canvas 2D architecture.

## Application guidance

- Wrap multi-record operations in `store.transact()`.
- Avoid calling `editor.render()` directly; use editor operations, which coalesce rendering.
- Keep image dimensions reasonable and release temporary object URLs.
- Use production builds when profiling.
- Test realistic mixed documents—not only thousands of identical rectangles.

## Targets

Interactive pen, pan, and zoom operations target a p95 frame time of 16.7 ms and treat p95 above 24 ms as a release regression. Large-document tests cover 100, 1,000, 4,000, and 10,000 shapes and record visible-versus-total shapes, first render, update batches, frame time, and retained heap.

The next major optimization is a per-page spatial index. Existing culling prevents offscreen drawing, while spatial indexing will also prevent scanning every offscreen shape.

Use `editor.getPerformanceSnapshot()` to read recent render timing. It reports
the last, average, and p95 duration across up to 120 frames plus the current
shape count. Pass `true` to read and reset the sample window.
